# Portfolio Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Реализовать и открыть в браузере личное портфолио с Avadas как главным кейсом.

**Architecture:** Семантическая статическая страница с CSS и небольшим JavaScript. Локальный Node HTTP-сервер обслуживает только разрешенные ресурсы; прием обращений в частном предпросмотре выключен. Серверный обработчик предусматривает явную настройку приема, валидацию и идемпотентное сохранение.

**Tech Stack:** HTML, CSS, JavaScript modules, Node.js 24, node:test. Без установки зависимостей для локального предпросмотра.

**Spec:** ../specs/2026-11-05-portfolio-design.md

## Global Constraints

- Русский язык. Avadas — прототип; сигнал и краткая рекомендация для самостоятельного входа.
- Не создавать вымышленные отзывы, контакты, доходность и скриншоты Avadas.
- Семь смысловых секций, основной CTA «Обсудить задачу».
- Светлая палитра, Manrope + Golos Text с системным fallback.
- Успех формы только после реального серверного подтверждения.
- Не запускать публичный сбор до получения настоящих реквизитов и настройки обработки.

## Review Focus

- Повторная отправка не создает вторую запись: тест concurrent idempotency.
- Ошибка хранения не дает ложный успех: тест storage failure.
- Необработанная конфигурация не принимает личные данные: тест disabled intake.
- Секреты, обращения и исходники не доступны через HTTP: тест static allowlist.
- Контент доступен без анимации и на телефоне: ручная проверка в браузере.

## Execution decisions

Native execution применяется в текущей сессии на основании одобрения ТЗ и ранее данного запроса разработать и открыть сайт. Повторное разрешение на ту же разработку не требуется. Работа начинается с локального предпросмотра; публикация и работоспособный публичный прием требуют условий раздела 11 ТЗ.
